# Agent Note: 并行解析对齐区不再静默丢弃畸形记录

Status: implemented

## Problem

`ParallelParsePipeline::findFirstRecordStart`（`src/pipeline/parallel_parse_pipeline.cpp`）
的假警报回退路径会对未通过结构校验的候选（quality 长度 ≠ sequence 长度、缺 `+` 行）
整体跳过并向后续扫。若该畸形记录恰好落在块边界之后的**对齐区**，任何 worker 都不会
解析它，但顺序路径会对同一输入抛 `kFormatError`。结果是：并行压缩产出一份自洽、
`verify` 通过的归档，却悄悄少了一条记录——直接违背工具的无损契约。日志统计的
`logicalBytes` 仅用于展示，没有任何总量兜底校验，丢失无法被检出。

顺带确认的相邻问题：原扫描从 `chunkBegin` 无界向前走，无候选数据（二进制垃圾）时
每个 worker 读到 EOF，O(K·N) 浪费后产出空块。

对抗性复查（2026-10）确认第一版修复仍有一个静默丢形状：畸形记录**只有 id 行**
（缺 body）、下一条记录头被吞时（字节流 `@r1\n@r2\n…`），`@r1` 结构拒绝后被当
假警报跳过，`@r2` 在 p=1 且残段仅 1 行时被放行命中——`@r1` 静默丢失、`@r2` 作为
"合法记录"被接受。

## Decision

对齐扫描重写为**有界窗口 + 结构拒绝即返回**：

- 窗口固定 7 个非空行（块边界至多落在记录起点前 3 行，校验起点记录又需 4 行；
  记录内空行为顺序路径拒绝的形状，不进入窗口）。
- 候选只按顺序路径的结构验收（`'@'` 头、`'+'` 行、长度相等）接受；内容校验
  （IUPAC 等）仍留给 `encodeFrame`，避免对内容畸形静默跳过。
- **结构拒绝的 `@` 候选不再跳过**：仅当其能判定为上一条记录的 `'@'` 质量行
  （Phred+33 Q31）残段时才跳过（质量行判定：p≥1 时其前一行以 `'+'` 开头，
  p==0 时被丢弃残段的首字符是 `'+'`）；否则**返回该候选**，让 worker 的 parser
  在与顺序路径相同的位置报错。这同时堵住"空 body 畸形 + 被吞头"与"缺 `+` 行/
  长度不匹配"两类静默丢。
- 跳过假警报的行标记 `skipped`，后续候选的残段可行性计算排除它们；残段形状
  锚点（`'+'` 行）按物理顺序检查：可行形状 `[]`、`[qual]`、`['+', qual]`、
  `[seq, '+', qual]`。
- 窗口收满仍未命中即报错（对齐区含顺序路径同样拒绝的损坏数据）。
- EOF 收尾：带后继行的 `@` 候选仍返回（交给 parser 报与顺序路径一致的错）；
  无候选时按残段可行性收窄——≤3 行可行残段保守返回空（旧行为，`@` 质量行残段
  场景），否则报 `kFormatError`。
- 行长上限 `maxLineBytes` 传入扫描，超长行直接 `kFormatError`。

已知极限（信息论上不可消除）：质量行判定依赖 `'+'` 锚点。若畸形记录的**前一行**
恰好以 `'+'` 开头（如上一记录的质量行是 Phred+11 的 `'+'`），且畸形记录恰在
chunk 边界行首，会被误判为质量行跳过——概率极低的双极端，选择保守方向的代价
（可能误报合法输入的罕见情形）低于静默丢数据。

并行与顺序路径由此在"同一输入、同一失败"上收敛。

## Alternatives considered

- **只加一句注释声明跳过是预期的** — 无法接受：静默丢数据违反无损契约，且
  `verify` 与逻辑字节统计都查不出来。
- **对齐区跟踪"被跳过的字节"，末尾与 `logicalBytes` 对账** — 兜底有效，但"在哪报错"
  仍含糊；返回畸形候选的方案直接把失败点收敛到与顺序路径一致的位置，对账失去必要性。
- **质量行判定用"下一行以 `@` 开头"** — 会把"空 body 畸形 + 被吞头"（`@r1` 后
  跟 `@r2`）误判为质量行跳过，静默丢仍在；改用前向 `'+'` 锚点。
- **窗口上限放大到 64 行以容纳更多质量行残段** — 边界仍存在，只是推远；且
  不解决"残段形状不可行"的语义判定。7 行的上限由"块边界 ≤3 残段行 + 4 行记录"
  给出，是紧的。

## Consequences

- **收益**：结构畸形（长度不匹配、缺 `'+'`、空 body 吞头、垃圾填充）+ 后续合法
  记录在并行路径上与顺序路径一样大声失败；扫描有界，垃圾输入不再触发 O(K·N)
  扫描。
- **代价**：对齐区现在对"结构拒绝的 `@` 候选"保守返回（worker 解析报错），极罕见
  的合法输入（`'+'` 开头质量行 + 边界行首 + Q31）会被误报，可用 `--parse-workers 0`
  绕过；EOF 收尾的"≤3 行可行残段返回空"保留旧保守语义，是仅存的静默跳过面。

  缺 `'+'` 返回、空 body 吞头返回、空行跳过、EOF 前垃圾、超长行）+ 2 个集成回归
  （结构不匹配/缺 `'+'` 在对齐区必须 `kFormatError`）+ 既有 21 个用例全绿。
- 既有 byte-identical 门禁、`'@'` 质量行对抗、BUG-2 幻影记录回归全绿；debug +
